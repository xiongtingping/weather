## 1. 现状：五处交织（读代码核对，未改）

1. **篮子编译读「当前阶段」= 三阶段里最新的包络**。`runtime._compile_target_plan` 第 1073 行 `select_current_stage(...)`（`stages.STAGE_PRECEDENCE`，P1 > P0-M > P0），P0-M/P1 每来一份包络都能触发篮子重决策（宪章 51/77）。因此篮子路径里长着一堆只为 P0-M/P1 存在的规则：P1 本地 11:00 前不入座（67，runtime 1312）、P1 下单证据闸（119，runtime ~1360）、P0-M/P1 只加仓不开仓（74，`delta_v2_runtime.CHAIN_OPENING_STAGES`）、Kelly 加仓水位（137）、TAF 入篮走补腿通道（145，`P0M_TAF_ENVELOPE_RULE_VERSION`）、补腿只补链上发过的腿（143，`_completion_143_sent_shares`）。
2. **秤砣线的触发源是篮子编译写的事实行**。`tiebreak_lane.stage_first_decisions` 读 `basket_policy_training_fact` 的 (站, 日, 阶段) 首决策，再从事实行取 `probability_envelope_id`/`ws_snapshot_id`。P0-M/P1 的首决策是篮子编译在这两个阶段上跑出来的；评估表里 13 次触发有 12 次来自 P0-M（8）和 P1（4）。**篮子一旦只读 P0，秤砣线在 P0-M/P1 上断粮。**
3. **三张表把车道钉死为 'basket'，各线只靠 plan_id 前缀区分**。`basket_target_execution_cycles` / `auto_trade_decisions` / `basket_target_capital_reservations` 都有 `strategy_lane CHECK(strategy_lane='basket')` 加 `*_no_retired_lane_insert` 触发器；`lane_orders.send_lane_buy` 写 'basket'，只在 `plan_id` 上带前缀（`tiebreak_plan_`/`recycle998_`/`misbuyexit_`；线上 99,112 个周期全是 'basket'）。**篮子读「已持腿 / 待成交 / 链上发过的腿」的查询不按前缀过滤**（`production_io` 2131 行起的 intents/reconciliations 汇总、`_completion_143_sent_shares`），所以秤砣线买的腿会被篮子当成自己链上的腿：143 会围着它补腿、135 会替它撤单、144 会把它当错买腿卖回。今天没出事只因为篮子车道关着（146）。
4. **资金没有车道份额**。`runtime_config.resolve_target_remaining_budget` 一个全局旋钮 + 宪章 141 的真实余额；秤砣线 `_cash_refusal` 自己读现金。两条线同时开就是同一口锅。
5. **证据、账本、禁入站、看板都按阶段或站日，不按车道**：纸面账本重放三阶段（`PAPER_LEDGER_STAGES`）；λ/β/L4 证据表按阶段收（140）；`auto_station_exclusions` 读全部实盘成交；看板的钱按站日。

快车道（153）已经把 TAF/METAR 入库后的 P0-M/P1 提到周期最前面（METAR 入库→P1 中位 3.4 / p90 7.0 分钟），随后才是意图对账与决策——这正是 B 线需要的时序基础。

## 2. 隔离契约（六条，任何车道都要满足）

**契约一：阶段可见性显式声明。** 每条车道声明它读的阶段集合，编译入口按声明过滤：
- 篮子：`compile_target_plan(..., stages=("P0",))`——worker 把 `load_materialized_probability_envelopes` 的结果先过滤到 P0 再交给篮子编译；`select_current_stage` 在篮子路径上只会看到 P0。篮子的决策时刻（77）只由 P0 概率身份变化触发；P0-M/P1 包络的到来不再触发篮子重决策。
- B 线：只读 P1 包络（`p1_observation_likelihood_json` 回执 + `prediction_root` 链）和报文时刻的 WS 快照。
- 秤砣线：读三阶段各自的**首个包络**（不是首个篮子决策）+ 该包络决策时刻的最新快照。

**契约二：站日所有权登记。** 新表 `strategy_lane_claims(station_id, event_date, bucket, lane, claimed_at_utc, order_intent_id, state)`：任何车道下 BUY 前先登记，同一 (站, 日) 已被别的车道登记 → 拒绝，理由 `station_day_claimed_by:<lane>`。默认**站日级互斥**（先到先得）：秤砣线和 B 线同一站日不会各买一个互斥的桶；篮子（P0，盘前/挂牌期）先占的站日，B 线与秤砣线不再进入。可配置 `claims.grain = station_day | station_day_bucket`（待裁）。

**契约三：归因不靠前缀猜。** 短期不动三张表的 CHECK（50 GB 库重建表不可行）：`strategy_lane` 列继续写 'basket'，**车道真身以 claims 表 + `plan_id` 前缀为准**，并把篮子读自己链的四处查询（已持腿/待成交/链上发过的腿/撤单候选）改为只读 `plan_id LIKE 'plan_%'`（篮子自己的），143/135/144 因此只作用于篮子腿。长期（下一次不可避免的迁移时）放开 CHECK 为 `IN ('basket','tiebreak','p1_likelihood',...)`。

**契约四：资金按车道分份额。** `strategy_lanes_v1.json` 每车道加 `budget_share`（三条买入线之和 ≤ 1）；车道敞口 = 该车道 active 预留 + 该车道持仓成本（按 claims 归因）；超份额拒（`lane_budget_exhausted`）。宪章 141 的 6.5%/8% 站日封顶只管篮子；B 线、秤砣线各自的单笔 stake 与站日一次即其封顶。

**契约五：门与证据各归其主。** 宪章 119（P1 证据闸）从篮子路径撤下，改成 B 线内部条件（回执 `state=APPLIED` 才允许买）；宪章 67（P1 11:00 前不入座）从篮子撤下，由 B 线的窗口规则（剩余 6–10h）取代；宪章 125（已报最高硬地板）三条线各自读——篮子只在它的决策时刻读一次。

**契约六：评估与账本各归其主。** B 线自己的评估表 `p1_likelihood_lane_evaluation`（每份报文一行：市场先验、g、β、信念、卖一、触发/拒绝、发单、成交、结算），仿 `tiebreak_lane_evaluation`；纸面账本只判篮子（`PAPER_LEDGER_STAGES=P0`），λ/β/L4 证据只收 P0 行——**P0-M/P1 包络没有 band 回执的问题随之消失**；禁入站与看板的钱按车道拆列。

## 3. 各车道的信念与策略

### A 篮子（P0）
- 信念：P0 校准后的分布（校准只在这里：中心/宽度、band）。
- 决策时刻：P0 概率身份变化（新 run 重根）；不再因 P0-M/P1 重决策。
- 选桶/定注/目标函数：现行 56/64/68/125/130/131/141 不动；补腿 143 只补自己发过的腿；撤单 135 只撤自己的挂单；144 只卖回自己的错买腿。
- 退出：只有 0.99 回收线。
- 现状：车道关着（146）。隔离改造在关着的状态下做，风险最低。

### B P1 似然线（新）
- 信念：`b = 市场先验(报文前 1 分钟中价，归一) × 硬下界 × g^β`，β 按剩余小时分档（实测：≥10h 0、6–10h 0.5–1、<6h 不交易）。
- 触发：每份新报文的 P1 包络（快车道产出），只在剩余 6–10h 窗口。
- 选桶：`b_k − 卖一_k ≥ 8¢` 的桶里取差最大的一个。
- 定注：固定 stake（旋钮），FOK 按卖一梯走深，交易所最小手以下不下单。
- 频率：一站日一桶一次；报文龄 > 8 分钟不买（edge 5 分钟后衰减、15 分钟归零）；FOK 被杀按秤砣线的规则在更新的盘口上重试至多 3 次。
- 退出：只有 0.99 回收线（15 分钟后按买一平仓实测 −0.067/$、13 天全负）。
- 上线路径：先影子（评估表、不下单）；14 天后复核三硬条件（日聚类 95% 下沿 > 0、13 天里 ≥ 9 天正、前后半段同号）；过了再由裁决打开 `lanes.p1_likelihood.enabled`。

### C 秤砣线
- 规则、stake、评估表不变。
- 只换触发源：`stage_first_decisions` 改读「阶段首包络」（`basket_probability_envelope` 按 (站, 日, 阶段) 取 `MIN(decision_at_utc)`）+ 该时刻的最新快照。回放 08-15 起的历史，核对 13 次触发与现评估表逐条一致后才切换。
- 与 B 线的关系：站日级互斥（契约二）；B 线只在下午窗口、秤砣线多在首决策（清晨/挂牌），实际撞车少，撞上先到先得。

### P0-M
- 不交易。TAF 似然对市场先验无信息（150 个 TAF 到达：−0.063 nat [−0.186, +0.020]，三种信念买入全负）。
- 保留：作为 P1 的根、作为「TAF 到达」的时刻标记、作为秤砣线的一个阶段首包络。
- 宪章 151 强开的闸只影响 P0-M 包络形状（进 P1 的根），不再影响任何下单；是否关回去待裁。

## 5. 落地顺序（每步可单独回退，每步有测试）

0. **只读审计**（半天）：脚本按 plan_id 前缀重算历史「已持腿/链上发过的腿」，证明现有篮子决策没有读进过秤砣/回收线的腿（预期：篮子关着，无交叉）；建 claims 表并回填历史 BUY。
1. **篮子隔离到 P0**（一天）：worker 只把 P0 包络交给篮子编译；删篮子路径上的 67/119/74/137(P0-M,P1)/145 分支；四处读表加前缀过滤；`PAPER_LEDGER_STAGES=P0`、证据表只收 P0；账本指纹换、全史重导。测试：篮子编译收到 P1 包络也不改变决策；秤砣腿不进篮子的持腿；ledger–production 绑定测试。篮子车道保持关着。
2. **秤砣线换触发源**（半天）：包络首决策 + 快照；回放核对 13 次触发逐条一致；评估表不变。
3. **B 线影子**（一天）：`p1_likelihood_lane.py`（信念、选桶、评估表、不下单）；日频复核脚本；看板一节。
4. **资金份额 + 禁入站/看板按车道**（一天）：`budget_share`、车道敞口、禁入站按车道、看板钱按车道。
5. **B 线上线**（裁决后）：`send_lane_buy` 接入、claims 登记、FOK 重试；第 154 条落地。
