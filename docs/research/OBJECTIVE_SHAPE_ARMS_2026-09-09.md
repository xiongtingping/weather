# 目标函数与份额形状：2026-09-06 结论的重测（2026-09-09）

> 用户提了一份目标函数改造方案（CRRA 效用 + 鲁棒概率集 + 形状候选化），我用 09-06 的臂实测否决了其中两条。
> 用户回：「重放账本，以上数据有可能会过期，先别否定，用数据说话，再重新评估方案。」
>
> 结论：**用户是对的，两条都必须重判——但重判后一条翻案、一条反而更硬。**

## 为什么必须重测

09-06 那次读数之后落地了宪章 93、94、103、110、112、116、119、120、121、122。其中三件直接动了被测对象：

1. **形状实现被重写**。`edge_weighted` 从「份额 ∝ max(edge,0)/最大edge，地板 0.15」换成
   `floor_first_edge_weights_v1`（先铺等份底仓，再把 `1−K` 的余量按可实现 edge 分出去；`Σw·c` 恒等、
   支持集内地板按构造非负）。换掉的原因写在函数文档里：旧形状的地板是**最优腿权重**的一个比例，
   跟篮子成本无关，宪章 93 把地板抬到 0 之后，09-08 那本账里**每一个** `edge_weighted` 候选都被地板拒掉
   （SAEZ 读 −0.246 对 0.30 权利金）——那条臂从来没能真正下过单。
2. **执行族换了**（宪章 94，吃单→挂单阶梯），成交面完全不同。
3. **基线自己翻正了**（见下）。在负基线上排出来的臂序不能搬到正基线上。

## 先修两个阻断（都已入库）

跑臂之前账本根本起不来，两处都是「生产与账本只改了一边」：

- `2504ca0a`：宪章 122(五) 给账本三处加了 `symmetric_seat_bands=`，运行时只给两处加了参数，
  漏掉的恰是求解入口 `_solve_over_support_windows`。**从 c032ea92 起任何生产裁判重放在第一个站点前就
  `TypeError`**。band 属于窗口枚举，枚举那一步已经读过它，求解器拿到的是枚举好的窗口——多余的声明删掉即可。
- `eacd0bff`：**账本裁判把目标形态写死了**（`Kelly if bankroll>0 else value`），从不读
  `CHARTER_72_KELLY_SIZING`；而指纹在开关离开 `on` 时会重新哈希。于是
  `PM_CHARTER_72_KELLY=off` 换了个摘要、判的还是 Kelly 律。修之前实测：该臂 278 仓位 / 151 结算 /
  投入 873.212 / 盈亏 +31.788，**与基线逐字段小数点后全同，两个不同指纹**。
  `_CURVE_OBJECTIVE_FORM` 在账本里导入了却从未使用——那个死导入就是线索。

两笔修复默认指纹都不变（`0b0a4ae769f2`），标准账本不动。

## 方法

- 小库 `build_ledger_replay_db.py --since 2026-08-28`（5.7 GB，563 站日真值，窗口 08-28→09-08）。
- 冻结代码树（rsync 到 scratch、data 软链、用完即删），HEAD `56577eb5` + 上面两笔修复；
  期间 main 上另有 8 笔提交，逐一核对**未触及内核 / 运行时 / 形状**。

### 一、基线翻正了

+3.64%。历史上每一个基线读数都是负的（−0.44% / −0.45% / −2.08% / −12.96%）。
**09-06 的臂序建立在负基线上，不能直接搬用**——这一条用户的怀疑成立。

### 二、形状：「全负且单调」作废，但仍然不能上

净值上 S-edge (+5.46%) 优于 base (+3.64%)，S-tilt 差得更远（−11.28%，且开仓数腰斩 278→136，
说明宪章 93 的地板把旧形状挡在门外）。t 的剂量反应 **不单调**（t=0 +3.64%、t=0.5 +1.36%、t=1 +5.46%），
这本身就说明差距在噪声量级。

链级配对（base vs S-edge，按 站×日×阶段）：

| 集合 | 席位 | 投入 | 盈亏 | ROI |
|---|---|---|---|---|
| 只在 base | 24 | 199.46 | +6.54 | +3.28% |
| 只在 S-edge | 16 | 78.18 | +33.82 | +43.26% |
| 两边都有 · base | 127 | 673.75 | +25.25 | +3.75% |
| 两边都有 · S-edge | 127 | 660.51 | +6.49 | +0.98% |

两边都有的 127 条里，87 条逐分相同，**40 条被重定份额：盈亏 −19.80 → −38.56，命中数不变（16→16）**。
即 **形状分量本身是负的 −18.76**，净值为正全靠只在 S-edge 出现的 16 条席位。
这 16 条里前 3 条就贡献了 +37.56（111%）：

    ZGGG 2026-09-03 P0   投入 5.46   +20.54
    MPMG 2026-09-06 P0   投入 5.40    +9.60
    ZGGG 2026-09-07 P1   投入 5.58    +7.42

**剔 1 个赢家，S-edge 相对 base 从 +8.52 掉到 −12.02**（剔 2：−21.62，剔 3：−29.04）。
按 09-06 那份文档自己用的剔赢家标准，这条臂当场不合格。
席位集合两边互有出入，命名的头号原因两个方向都是 `support_floor_after_lift`（宪章 93）——
形状改变的是哪些篮子能过抬手后的地板复检，这正是 floor-first 形状的设计意图。

**修正后的结论**：09-06 的「随倾斜强度单调变差」已作废（那测的是一个连坐都坐不下的实现）；
新实现的形状分量实测为负，净值差 +8.52 USDC 落在本账自己的干扰底噪内（±15 USDC，见 c032ea92），
且由单一席位决定。**默认保持 `equal`，理由换成「形状分量为负、净值不显著」。**

### 三、统一目标接管定注：重放后结论更硬，不是更软

这是修完 `eacd0bff` 之后第一次真正测到这条臂。

**+3.64% → −17.85%**，差 21.5 个点 / −180.42 USDC。剔掉最差 1/2/3 条链后仍是 −167.40 / −154.97 / −143.13，
**广泛而非单点**。链级配对：两边都有 97 条，其中 83 条被重定，盈亏 −108.46 → −174.25、命中 28 → 26、
投入反而略降。

形态与 08-12 记录的老毛病一致：**买得更多**（326 仓位 vs 278）、**窗更窄**（均宽 1.85 vs 1.99）、
**命中更低**（42.1% vs 47.7%）。原因在曲线目标的风险旋钮上——

    curve_score 的有效本金是 W/f。分数 Kelly 的正确等价是 W·f，不是 W/f。

用内核自己的求解器验（三档支持集，声称 0.30/0.20/0.10、价 0.22/0.15/0.08、W=30、深度与预算都不绑）：

| | 注额 |
|---|---|
| 全 Kelly（本金 W） | 8.182 U |
| 分数 Kelly 正解 `f·q*(W)` | 2.045 U ＝ 0.25× |
| 生产曲线口径 `q*(W/f)`、f 传 1.0 | **32.727 U ＝ 4.00×** |

差 16 倍且方向相反。账本自己的注释早就说出了后果：
*"the station cap (15 USDC), which the kernel widens by 1/f to 60, so at stakes under 6 the curve is a line
and the objective is expected value."* 所以「关掉第 72 条回到统一目标」在今天这套约束下**不是**一个更保守的
效用目标，而是一个近似风险中性、把额度花光的目标——账本读数正是这么表现的。

## 对方案的意义

- 提案第 4 条（形状候选化、t 网格）：`PM_KELLY_EDGE_TILT_FRACTION` 已经是现成开关，不必新建装置；
  但形状分量实测为负，**不因为目标函数换成 CRRA 而改变**——重定份额的那 40 条链命中数一个没多。
- 提案第 1/2 条（统一效用目标同时定仓位与形状）：在**修好 `W/f` 方向之前**不能测，测了也是测一个
  4× 全 Kelly 的 EV 最大化器；本次读数 −17.85% 量的就是那个东西。γ 显式化的价值因此从「命名清晰」
  升级为「先修反向旋钮」。
- 提案第 1 条的鲁棒集 `min_{p∈P}`：本次没测，仍是唯一没被任何账本证据碰过的部分。
