# M7 协议：合成 ΔT 补到当地 18–23 点（2026-10-21，先于读数提交）

熊先生 10-21「补上」（接在 0–8 点之后，补齐全天）。方法与 M6 相同。

## 1. 特征在 18–23 点的定义
| 特征 | 18–23 点的取法 |
|---|---|
| 气温差、露点、湿度、风 | 06..H 点里最新一个报文与日前预报都有的小时（与 9–17 点同一规则，延长到 H） |
| 降水 | 06..H 点报文有降水的小时数 |
| 日照 sw | 06..17 点平均：17 点后日照可以忽略，卫星在傍晚也常缺，所以停在 17 点 |
| 物理核 phys | 同 17 点：只累计到 15 点，18 点后与 17 点相同 |

数据：`features.py` 给每个站日补上 18–23 点的报文与日前预报，其余字段不变。

## 2. 臂与判定
- 与 M6 相同：每个 H 比较 ⑥（A＋B 按站，k=100）与 ①（只用站点平均偏差），逐日前推，LogScore 主裁，按事件日 3 天一块自助。
- ⑥ − ① 的 LogScore 区间上界 < 0 的小时才上图；不过关的小时不画。

## 3. 已知局限（写在读数之前）
- 到了傍晚，最高温通常已经出现，最有用的信息是当天已观测到的最高温；本方法的特征里没有这一项。
- 本轮按熊先生「同样方法」只补小时，不加新特征。要不要加「已观测最高温」，读数出来后另立协议。

## 4. 版本与口径
- 同 M3／M6；48 站。
- 0–17 点的定义与读数不受影响。
- 本协议提交时尚未看过任何 18–23 点读数。
