# 单系统校准按 LogLoss 重拟：不切换（面板四项未同时变好）

协议见 [PROTOCOL.md](PROTOCOL.md)（计算前写定）。只读，生产未改。复现：`capture_ll.py`（三组并行约 50 分钟）→ `pass1/`（未提交，可重建）→ `score_ll.py` → `results.json`。

## 结论

现行单系统校准用矩估计：偏差取半衰加权平均误差，宽度取残差σ除以成员离散。按事先写定的面板判据，把它换成按桶 LogLoss 拟合，**两个臂都不过**：

- **只重拟宽度**：LogScore 显著变差（+0.0106，区间 [+0.0019, +0.0200]），Resolution 显著变好，Brier 和 Reliability 不显著。
- **中心和宽度一起重拟**：桶 Brier 和 Resolution 显著变好，LogScore 变差（+0.0058，区间跨零），Reliability 不显著。

训练窗里 LogLoss 拟合把 NLL 从 1.556 压到 1.487，换到样本外 LogScore 反而升高。偏差的半衰期只有 5 天，有效样本少，LogLoss 拟合在少数 scope 上把分布收得过尖，偶尔的尾部失手把 LogScore 拖回去。**判定：现行矩估计在服务面上不输，符合宪章 211，不重拟。** 中心加宽度一起重拟带来的 Brier 和 Resolution 改善是真的，只是被 LogScore 的代价抵消，记为线索，见最后一节。

## 拟合出的参数（122,451 次拟合）

- **宽度**：生产 spread_factor 中位 1.414。只重拟宽度的中位是 1.297，与生产之比的 p10/p50/p90 为 0.71/0.93/1.18，LogLoss 普遍要更窄。
- **中心平移 δ**：p10/p50/p90 为 −0.30/0.00/+0.34°C。
- **训练窗内 NLL**：生产 1.556，只重拟宽度 1.517，中心和宽度一起重拟 1.487。样本内全部更好，样本外 LogScore 全部更差。

## 装置与复核

- **对拍**：生产臂和 `fusion_blend_historical_20260923` 第一遍的席位臂逐次一致。EGLC 共同的 691 次更新，服务得分逐项相同。本次多出的更新来自今天回填的 AIGEFS 历史。
- **拟合函数**：拟合用的向量化真值桶概率，在每一次拟合的训练行上与生产 `_apply_parameters` 对拍，误差不超过 1e-9。第一次试跑发现 numpy 的求和顺序会让恰好落在三档切点上的样本判到另一档（RPLL），已改成与生产相同的求和顺序，全部 45 站重跑。那次不完整的 31 站读数作废。

## 线索（未验证，不作结论）

中心和宽度一起重拟，在所有切片上 Resolution 都显著变好，主读数和宪章 134 之后的 Brier 也显著变好，代价全在 LogScore。这和 LogLoss 在短窗上把分布收得过尖的样子一致。一个加正则的版本（更长的拟合半衰期，并向生产参数收缩）也许能留住 Resolution、去掉 LogScore 的代价。但它是看过本次结果后才提出的新臂，必须另立协议、在未参与本次观察的新日子上验证，不能拿本次数据挑参数。
