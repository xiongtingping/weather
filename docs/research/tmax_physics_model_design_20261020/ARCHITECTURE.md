# 当日最高温增量模型：系统架构设计（2026-10-20，待裁）

熊先生 10-20：「日照的增幅推断的最高温增幅，拟合计算方法不对，用历史数据，重新计算……区分站点……最好建模：模拟太阳辐射、云、雨、露点、湿度、太阳高度角、风等所有影响温度的模型，先设计架构」。

本文只是设计，不改生产、不读写 SSOT；输出只上看板，不进 P0/P0-M/P1。

## 0. 现行算法错在哪
现行是看板卡片「日照推算最高温」，参数文件 `config/ui/sun_tmax_shift_v2.json`，拟合脚本 `sun_tmax_shift_abs_20261017/fit.py`。

| 问题 | 现行做法 | 后果 |
|---|---|---|
| 不分站 | 全队一条两段折线，y 只减站均值 | 干燥内陆站和潮湿沿海站，每 100 W/m² 换算成的温度不同，却共用一个斜率 |
| 样本太短 | 只用 09-01..10-06，约 36 天 | 想分站拟合也拟不出来（第 76 轮按站斜率不成立的原因之一） |
| x 的口径粗 | 05..H 点短波差直接平均 | 07 点多出 100 W/m² 和 12 点多出 100 W/m²，对最高温的作用差几倍，现在按同样权重算 |
| 各变量各拟各的 | 日照、云、露点、湿度、风各一条线，卡片注明「不可相加」 | 没有一个合起来的 ΔT；湿度和日照的重叠无法分开 |
| y 混入了别的误差 | y＝真值 − 日前预报最高温 | 平流、海风这类与日照无关的误差都在 y 里，斜率被压低，R² 只有 0.06–0.21 |

## 1. 目标与终点线
- **输出**：每站、每个已测到的小时 H，给出「真值 − 日前预报最高温」的估计 ΔT 及其分布，并拆成日照、湿度/露点、风、云、雨几项贡献，几项相加等于总 ΔT。
- **终点线（可验证）**：逐日前推、按事件日块自助，按宪章 240 口径（MAE 与 LogScore）比较：
  - 合成 ΔT 在 9–17 点每个小时都显著好于现行日照线；
  - 也显著好于现行最强的湿度线；
  - 按站报，多重检验用 BH。
- 达不到就不替换现行卡片，只报读数。

## 2. 总体结构（三层，物理在前、统计兜底）

```
 静态站点档案 ─┐
 历史训练库 ───┼─► A 物理核（逐站参数） ─► ΔT_phys（差分）
 今日驱动 ─────┘          │
                          ▼
              B 站点残差层（分层收缩） ─► ΔT 点估计 + 各项贡献
                          │
                          ▼
              C 集合与分布层 ─► ΔT 分布 → 最高温各桶概率（看板）
```

### A 物理核：地表能量平衡＋混合层（slab）模型，按差分运行
- **状态**：近地面温度 T、比湿 q、混合层高度 h，按小时从日出积分到最高温时刻。
- **能量平衡**：净辐射 Rn ＝ (1−α)·SW↓ ＋ LW↓ − εσT⁴ ＝ H ＋ LE ＋ G。
  - SW↓ 已过去的小时用卫星实测，未来小时用预报；
  - LW↓ 由云量、气温、露点估算；
  - 感热与潜热的分配用波文比 β 控制（参考 Porporato 2009 常数波文比 slab），β 由近几日降水和露点亏损调节；
  - 地中热通量 G 取 Rn 的一个固定比例。
- **混合层**：h 按感热通量在早晨稳定层结中增长，温度增量 ≈ 累计感热 /(ρ·cp·h)。早晨直减率取自 NWP 的 850 hPa 温度。
- **风**：增大混合与夹卷；沿海站加平流与海风项（偏差 × 风向分量，参考 `wind_tmax_shift_20261019` 的南北分量读数）。
- **关键：差分运行**。同一模型跑两遍，一遍用「日前预报驱动」，一遍用「已测小时换成实测、其余仍用预报」，两者之差就是 ΔT_phys。模型本身的绝对偏差在相减时消掉，只剩敏感度，这也是物理模型在这里最可信的部分。
- **逐站参数**（每站、按季节，从历史拟合）：
  - 反照率 α；
  - 波文比 β₀ 及其对降水/露点的响应；
  - 有效混合层深度系数；
  - G 的比例；
  - 沿海平流系数；
  - 地形订正（海拔、谷地/高原，读现有 `listing_forecast_f_terrain_v1.json`）。

### B 站点残差层：类 MOS，分层收缩
- **y**：真值 − 日前预报最高温；按最后测到的小时 H 分开拟合。
- **特征**：
  - ΔT_phys；
  - 湿度差、露点差、风速差与风向分量；
  - 降水与近日累计雨；
  - 短波差按剩余升温加权的版本（权重 ∝ 太阳高度角 × 距峰值时刻）。
- **分层收缩**：站系数 ＝ 全队系数 ＋ 站偏离，偏离向地形组收缩（沿海、高原/盆地、干旱、热带）。与现行站×模型权重同一思路（宪章 242 的 EBP）。
- 每个特征的贡献单独记录，卡片据此显示「日照 +0.4、湿度 +0.2、风 −0.1……」。

### C 集合与分布层（参考全球原始成员→桶的做法）
- **两路抽样**：
  - 未来小时的驱动取各成员的逐小时预报；
  - 参数从 B 层后验抽样。
- 每个抽样跑一遍 A＋B，得到 ΔT 的样本。
- 用与 P0 相同的分布构造，加宽核再按市场梯子求和，得到「日前预报最高温 ＋ ΔT」在各桶上的概率。
- 校准按宪章 259 的 A 层：LogScore 主裁，另报 CRPS 与 PIT。

## 3. 数据架构

| 用途 | 来源 | 现有长度 | 需要 |
|---|---|---|---|
| 评估真值 | `calibration_station_daily_high_truth`（正式两车道） | 06-28 起，48 站 | 只用于评估 |
| 逐小时实况（T、Td、风、云、天气） | `basket_target_observation_facts`（AWC/ASOS） | 08-21 起 | 多年历史另取 IEM METAR（09-24 已裁「可以」作训练数据，行标 aggregator、单独存放） |
| 日前预报逐小时 | Open-Meteo `previous_day1` | 研究缓存约 09-01 起 | 多年历史需 Open-Meteo historical-forecast（研究额度，走生产账本 lane=research，按天限速） |
| 实测短波 | JAXA L3（17 个亚洲站，P-Tree 有多年存档）、GOES DSR（美洲）、MSG/SARAH（欧非） | 看板缓存只留 96 小时 | 历史需逐区补抓；缺区退 ERA5 短波作代理，并标明 |
| 土壤湿度、反照率 | ERA5-Land / MODIS | 无 | 只取站点格点日值 |
| 原生 NWP 物理量（850 hPa、短波等） | `data/deterministic_point_physics.db` | AIFS 8-26、其余 9-01 起 | 只作当日驱动，不作多年训练 |

- **分开存放**：训练库放 `data/tmax_physics/` 下独立 SQLite，不进 SSOT（宪章 267 补记八同理）。
- **lineage**：每行带来源与 aggregator 标签。
- **资源**：抓取流式、有硬上限，盘余量低于 MIN_FREE 即停。

## 4. 训练与评估协议
1. **训练窗**：多年历史（目标每站 ≥3 年 × 当季 ±45 天），拟合 A 层的逐站参数和 B 层系数。
2. **检验窗**：09-01 起逐日前推，每天只用当天之前的数据重拟。
   - 对照臂：①只用均值；②现行日照线；③现行湿度线；④只有 B 层（不含 ΔT_phys）；⑤ A＋B；⑥ A＋B 按站。
   - ⑤ 对比 ④ 用来回答「物理核有没有增量」，⑥ 对比 ⑤ 用来回答「分站值不值」。
3. **口径**：按宪章 255 写明版本与口径；多年历史只用于训练，判定只看检验窗。
4. **协议先于读数提交**，判据不中途改。
