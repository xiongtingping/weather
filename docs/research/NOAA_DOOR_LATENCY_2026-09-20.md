# 两道门谁更快：AWC 对 NOAA TGFTP（2026-09-20 实测）

**结论：不要把 TGFTP 从「AWC 全灭才用」改成「AWC 慢过阈值就用」。对美国站它系统性滞后
2.3–8.2 分钟。宪章 162 的现状是对的。**

## 为什么测

09-20 下午 AWC 单次请求从中位 0.13 秒劣化到 10–18 秒（14:52 起，16:30 后自行恢复到
1.47 秒）。宪章 170 的快车道把轮询半周期压到 2.5 秒后，剩下的延迟几乎全在上游，所以问
题变成：另一道门是不是更快。

## 怎么测

两条门并行打（同一线程池、同一秒发起），用的是生产函数与生产参数：
`fetch_awc_temperature_reports(stations, hours=2)` 与
`fetch_noaa_tgftp_temperature_reports(stations, cycles=2)`，48 站全名册。
对每一份报文记两条门各自**第一次能给出它**的时刻——不是比两边「当前最新」，那会把
「上一份 vs 新一份」的间隔误读成领先量（第一轮分析就掉进过这个坑，读出假的 +30 分钟）。

- 批次 A：16:30:28–16:38:43Z，16 轮 × 33 秒（覆盖 `:30` 国际站到达窗口）
- 批次 B：16:50:00–16:59:32Z，27 轮 × 22 秒（覆盖 `:51–:58` 美国站到达窗口）
- 收尾点查：17:00:22Z

## 判例

**只测一个到达窗口会把结论读反。** 批次 A 单独看是 TGFTP 胜（+0.55 分钟），批次 B 是
AWC 胜（≥ +2.3 分钟且全部 11 份）。差别是两道门的组织方式：AWC 是按查询窗口取的实时
接口，TGFTP 是按小时 cycle 归档的公报文件，后者对「本小时刚发的」天然滞后到整点。美国
名册全部在小时末尾发报，正好落在 TGFTP 最弱的位置。

## 顺带量到的

AWC 对美国站的发布延迟约 **1 分钟**（KLGA 16:51 报文 16:52:12 可得、KATL 16:52 的
16:52:56、KSFO 16:56 的 16:57:20）。宪章 170 的快车道在这个窗口按 5 秒轮询，所以接得住
——观测到入库约 1.1 分钟，对照上线前全队中位 3.9 分钟。

LLBG 在整个探测期间两条门都没有，最后一份报文是 11:50Z，停报近 5 小时；它不在实盘名册
也不在禁入表，P1 自 10:00Z 起没为它出过包络。是上游站点停报，不是采集问题。

# 追记（2026-09-21）：宪章 170 的立论前提是采集日志的伪象

上面那次门对比是在宪章 170 上线后做的。8 小时回读的结论是：**快车道按设计跑起来了，但
延迟没有任何可测改善**，而根因是立论时引的那个数本身错了。

## 被推翻的数

宪章 170 的缺陷（一）说「AWC poll 间隔中位 58.6 秒，而配置要的是 2.0 秒」。那个 58.6
秒不是轮询频率，是 `reported_trajectory_source_polls` 的**六十秒心跳**：

```python
# reported_trajectory_awc_ingress.process_source_poll
persist_poll = (
    has_new_candidate                      # 这轮带回了新报文
    or bool(poll.get("station_errors"))    # 有站出错
    or now_mono - last_persist >= 60.0     # 距上次落行满 60 秒
)
```

日志只在这三者之一时写行。上线前 4,769 个间隔的分布：

```
<5s      162   3.4%
5-30s   1164  24.4%
30-55s  1000  21.0%
55-65s  1889  39.6%   <-- 六十秒心跳
>65s     554  11.6%
```

近四成精确堆在 55–65 秒。中位 56.3 秒量的是心跳，不是 poll。慢车道一直按它配置的节奏
在轮询，「等主循环的班」不存在，由此推出的「94 秒里约 29 秒在等班」一并作废。

## 上线后实测

| | 上线前（慢车道） | 上线后（快车道） |
|---|---|---|
| 美国站 观测→到手 中位 | 1.42 分 | **1.44 分** |
| 美国站 p90 | 2.27 分 | 3.09 分 |
| 国际站 中位 | 3.62 分 | **3.27 分** |
| 国际站 p90 | 6.06 分 | 7.03 分 |

（等长 8 小时窗口，都取 AWC 健康期，剔掉 14:52–16:30 的上游劣化。前一天同时段不能作
对照：09-19T23:59:59Z 是 AWC 证书过期事故，它的 p90 55 分钟是事故不是常态。）

快车道自身：270 轮/小时（设计 287）、ingress 滞后 p90 0.114 秒、8 小时零错误、73% 的
取件落在学到的热分钟里。**它按设计跑了，只是设计解决的不是真问题。**

## 两个中途的误诊，都已收回

1. **「ingress 写锁是瓶颈，p90 12.4 秒」** —— 那 12.4 秒是我自己造成的。慢 ingress 全部
   落在 16:30–16:39 与 16:50–17:00，正是上面两批门探测在跑的时段（两个并行 fetcher，
   TGFTP 每轮下 3.2MB）。剔掉那两段后 p90 是 **0.119 秒**，新常驻期 0.114 秒、超过 5 秒
   的只占 1.0%。
2. **「快车道只跑到设计的 40%」** —— 拿 poll 日志的行数当轮次数，又一次踩进同一个心跳
   陷阱。车道自己的计数器是 270 轮/小时。

## 剩下的是什么

美国站 86 秒的「观测→到手」中位里，约 **72 秒是 AWC 的发布延迟**（KLGA 的 16:51Z 报文
16:52:12Z 才首次可得），我们的轮询只占几秒。换门这条路上面已经测过：TGFTP 对美国站反而
滞后 2.3–8.2 分钟。**这条延迟优化的路到头了。**

宪章 170 保留，但要按它实际买到的东西来估值：主循环忙时仍能取件的韧性，加一个跟着名册
自己走的窗口——不是延迟改善。
