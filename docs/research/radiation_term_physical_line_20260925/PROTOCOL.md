# 物理线 vs 温度线：P0 辐射降温项由 TAF / METAR 继承修正的信息增益判定协议（2026-09-25）

熊先生：「p0的辐射降温项，taf和metar应该继承和修正更新，并同步影响概率分布」→「taf报文的物理证据、和metar的物理证据和温度线是两条线，检查这个是否有信息增益」→「应该有数据，再找找」。只读，生产未改。

## 为什么用公开源复刻

本次会话在云端容器，生产 SSOT（`data/bayes_basket_target_ssot.db`、`data/archive.db`、`data/runtime/taf_raw_archive`）不在本机，本账号也没有能直连本机的会话或自托管环境；仓库内的抽取件只覆盖 09-10～09-13 的两三个事件日。故按生产读取的同一批上游，从公开源重建：

| 输入 | 来源 | 与生产的关系 |
|---|---|---|
| TAF（45 站，近 29 天） | AWC `api/data/taf?date=`，逐小时快照 | 与生产 `_forecast_features` 解析的是同一个 AWC 解码 JSON |
| TAF（美国 11 站，2025-06 起） | IEM TAF 档案，按份重组为 AWC 解码形态 | 与同期 AWC 解码对账：KATL 256 份 201 份逐位相同、KAUS 172 份 170 份相同，其余云/降水平均差 ≤0.0025 |
| METAR/SPECI 原文（45 站，2025-06 起） | IEM ASOS/METAR 档案 | 用生产 `parse_metar_physical_state` 直接解析 |
| 日前预报（逐时温度/短波辐射/云量/降水/风） | Open-Meteo previous-runs `*_previous_day1` | 生产物理表同源（Open-Meteo），但取的是「前一天说的」而非覆盖写的当天值，天然 as-of |
| P0 代理的温度中心 | 同上，ECMWF IFS / GFS / ICON / GEM 四家全球模式日最高的等权均值 | 生产 P0 是全球集合的校准混合；best_match 混了区域高分辨率模式，作敏感性臂 |

真值：站点当地日 METAR＋SPECI 最高（C 站整度 °C；F 站 T 组换算整数 °F），与结算合同同口径；日内 08–18 时每 2 小时至少一报才收。

## 两条线（每个阶段）

- **温度线**：P0＝日前最高＋本站指数加权历史误差（半衰期 15 天，≥10 天）、宽度＝加权残差 RMS（半衰期 30 天，下限 0.7°C），再加**生产同式的辐射项** 0.07×Kt z×σ（`forecast_clearness_shift_sigma`，本站事件日前 180 天）；P0-M＝P0 × 宪章 150 的 TX 似然（x＝TX−c₀ 对 y＝真值−c₀ 的直线，按站 K=15 收缩）；P1＝已报最高截断 ×「余下最高＝模式曲线余下最高（平移到根的水平）＋回归(近 3 小时新息、此刻偏差、余量)」。
- **物理线**：
  - P0-M：TAF 升温窗（当地 06–15）云/降水/风（生产 `_forecast_features`）；「修正」形式＝TAF 减模式同窗云/湿/风；「字面继承」＝按 Kasten–Czeplak 把 TAF 云相对模式云换成 Kt 修正，再以同一 0.07 系数平移，不拟合。
  - P1：METAR 此刻物理状态（生产 P1 已读：云、降水、风、露点差，记为 S）；已过日照时段的「实况−预报」云/降水/风（太阳高度加权，记为 el）；继承的 TAF 余下时段云/降水修正（taf）；P0 辐射项在 P1 重新加权（rad）。

所有臂一律逐日前推：事件日 d 的决策只用 d−2 及以前已结算的站日拟合（截距在所有臂里都有，物理项不享受偏差修正的功劳）。

## 判据（宪章 211：桶 LogScore 为主、桶 Brier 并看）

主比较（计算前写定）：

1. **P0-M**：`T+M+TAF` 对 `T+M`（TAF 物理在「温度线＋模式自身物理」之上），早间 TAF（当地 06:00 前最新一份），全样本。
2. **P1**：`T+S+el+taf+rad` 对 `T+S`（整条物理线在「温度线＋生产已读的此刻状态」之上），当地 08/10/12/14/16 时各一。
3. **P1**：`T+S` 对 `T`（METAR 物理证据相对纯温度线的总量；生产已在用，作锚）。

「有信息增益」＝ LogScore 与 Brier 的按日均值都为正、LogScore 按日自助 95% 区间下沿 >0、且前后两半同号。
「值得上服务」另需 ≥0.01 nat/决策（宪章 161 直接更新的服务闸量级）。
