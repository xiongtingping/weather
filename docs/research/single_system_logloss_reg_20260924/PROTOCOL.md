# 单系统「中心＋宽度」LogLoss 重拟的正则版：在未用过的日子上验证（计算前协议，2026-09-24）

熊先生：「验证」（针对 `single_system_logloss_20260924` 末节的线索）。

## 为什么要另立协议

上一轮（07-20..09-22）里，「中心和宽度一起按 LogLoss 重拟」让桶 Brier 和 Resolution 显著变好，代价全在 LogScore。样本内 NLL 下降、样本外 LogScore 上升，形状是过拟合。正则化的想法是**看过那批日子之后**才提出的，所以不能在那批日子上验证，也不能在那批日子上挑超参数。

## 样本：只用没参与过上一轮的事件日

- **历史段**：事件日 2026-07-01..07-19（最早有两个家族的日子；逐系统滚动训练窗至少 5 天，所以约 07-06 起才有可评更新）。
- **前向段**：2026-09-23（截止 2026-09-24T12:00Z 已结算的日子）。
- 训练窗照生产回放（60 天滚动、真值须在更新前可知、run 须在更新前到货），可以用到这些日子之前的任何已结算日。被评分的只有上面两段。装置与上一轮相同（同一生产重放、同一席位、桥接、形状栈、该小时服务表），每次拟合都与生产 `_apply_parameters` 对拍。

## 三个臂（超参数全部取生产现成常数，不挑）

- **生产 `prod`**：`oos._fit_parameters`。
- **未正则 `ll_both`**：上一轮原样（半衰期 5 天加权的 LogLoss，联合拟合中心平移 δ 与 spread_factor）。用来看上一轮的现象是否在新日子上重现。
- **正则 `ll_both_reg`（主臂）**：
  - LogLoss 加权半衰期取 `RELIABILITY_HALF_LIFE_DAYS = 15`，代替 5。
  - 拟合结果向生产参数收缩一半：δ_reg = 0.5·δ_LL，s_reg = 0.5·s_LL + 0.5·s_prod。κ=0.5 与稳定池的 `STABLE_POOL_KAPPA` 相同。
