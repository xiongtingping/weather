# OOS 门改读站点市场梯子：改判量

协议见 [PROTOCOL.md](PROTOCOL.md)（计算前写定）。只读测量，生产变更见宪章 213。复现：`measure.py`（按 as-of 与格子跑生产 `build_native_ensemble_oos`，写 `runs/`）→ `aggregate.py` → `results.json`。

## 结论

切到梯子上，证书判决变动 3.8%：两边共有的 5,034 个证书键里，**115 个由拒转准，74 个由准转拒**。没有任何「站×提前量」整组失去证书；细到「站×提前量×周期」，280 个里只有 SBGR h12_24 12Z 一个整组失准，另有 3 个从无到有。

白话：门以前拿 1°C 一格的尺子给模型打分，交易却按市场自己的格子结算。华氏站每格 2°F，约 1.11°C，两套格子对不上。换成市场的格子后，华氏站的模型分数明显变好，有 56 个证书因此从拒变准。

## 一个顺带修掉的读错

P0 的 band 车道拿门的留出期存档当第二套几何，命中判定写死为「中心 ±0.5°C」。这张表里早就混有 P0 前向预测写进去的梯子行。F 站一格 1.11°C，±0.5°C 的窗会漏判整格。例如 16.4°C＝61.5°F 应落在 62-63°F，但 60-61°F 的窗只到 16.33°C，62-63°F 的窗从 16.44°C 起，两边都够不着。现在非整数标签的行改按站日梯子区间判定，整度行保持原规则。
