# 结果：技能权重改用 LogScore 最优混合——两种口径都更差，不改

协议 f5892daf 先提交。六家 1–9 月走查，04-01..09-30，7,093 站日；34,041 个决策用上 LS 技能、1,200 个因样本 <5 天退回 MV。对照现役 MV（κ=0.25）。

| 口径 | ΔLogScore（LS−MV）[95%] | ΔBrier [95%] | ΔCRPS [95%] | 过门 |
|---|---|---|---|---|
| 席位 | +0.0056 [−0.0009, +0.0123] | **+0.0039 [+0.0023, +0.0055]** | **+0.0044 [+0.0014, +0.0076]** | 否（护栏破） |
| 席位 4–6 月 / 7–9 月 | +0.0000 / +0.0097 | +0.0019 / +0.0053 | −0.0014 / +0.0086 | |
| 服务 | **+0.0078 [+0.0048, +0.0105]** | **+0.0024** | **+0.0037** | 否（显著更差） |

读法：
- 按条件概率最直接的尺子去拟，反而更差。原因是信息量：中心误差是一个连续数，每天每家都给出"差多少"；桶 LogScore 只记"真值桶那一格给了多少概率"，60 天、同一提前量桶的样本上，它的最优解噪声大得多。最小方差在短窗上更稳。
- 服务口径更差得更明显：服务层（宪章 242）本身已经是站级 LogScore 拟合，席位先验再用同一种目标在更短窗口上拟一次，两层用的是同一种、且更嘈杂的信息；MV 先验提供的是另一种信息（误差协方差），两者互补。
- 这是第三次同一方向不过：09-24 融合层改 LogLoss、09-25 199 覆盖层改 LogLoss、本次席位技能改 LogScore。

结论：技能权重维持中心误差最小方差。口径"不一致"在这里是有意的分工：席位层用信息量大的连续误差定稳健先验，服务层用桶 LogScore 定最终分配。
