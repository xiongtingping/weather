# 预注册协议：技能权重的目标——中心误差最小方差 vs 桶 LogScore 最优混合

写于 2026-10-02，评分之前。裁决人：熊先生（「重测」，续「为什么席位权重这样设计」）。

## 问题
席位权重 = 0.75·技能 + 0.25·家族均分（宪章 244）。技能现由中心误差协方差求最小方差（`_seat_weights`），而 OOS 门与服务层（宪章 240/242）用的是桶 LogScore。目标不一致。
问：技能权重改用 LogScore 最优混合，席位与服务两种口径下是否更好。

## 数据与机器
`station_model_weights_20261001/pass1_all`（六家 1–9 月生产走查），score.py 代表决策、下游与评分。
- **现役 MV**：skill_mv = 2·seat_captured − 家族均分（捕获时 κ=0.5，反推），w0 = 0.75·skill_mv + 0.25·家族均分。即 `seat_weight_kappa_20261002/sd_k0.25`。
- **候选 LS**：每个决策，取本站、同一提前量桶（该决策最新桶）、事件日在 [d−60, d) 且真值在决策前已知的代表决策，在各自在座集合内归一打分，拟 softmax 桶 LogScore 最优混合权重（同 `fusion_blend.fit_theta`，单家真值概率 1e-3 下限）；少于 5 个站日时退回 skill_mv。w0 = 0.75·skill_ls + 0.25·家族均分。
- 两口径：席位口径（w0 直接下游）；服务口径（w0 作宪章 242 先验，τ 同法前推选）。
## 判决
计分 2026-04-01..09-30，宪章 240 门（簇=站日）。**主判决：席位口径** LS 对 MV 过门，且前后两段（04-06/07-09）ΔLogScore 同负；**护栏**：服务口径 LS 对 MV 不显著更差（ΔLogScore 95% 下界 ≤ 0）。两项都满足才提议改；否则不改。
