# 下一阶段：原生物理输入最小合同

本文件是输入合同，不授权或创建采集任务、不改变 active registry，也不把未来采集算作 OOS。

## 每条事实的键与时间

唯一键：station_id × active model-product × native run_init × member_id（若字段为集合成员）× valid_time × variable × source object hash。

必须保留：官方源 URL/对象路径、真实产品/变量定义、原单位与 °C/m/s 等转换规则、垂直层、网格提取方法、原生发布时间或可验证历史可用时点、本地请求开始/完成、首次 canonical 接收时间、覆盖的目标本地日、原始对象 hash。

原生 run 初始化不是发布时间；历史归档今天可下载不证明当时已收到。若研究使用官方历史发布证明而非本地旧 receipt，必须单独声明为“按公共可用性反事实回放”，不得混进“当时实际已收到”的主结果。

## 优先字段与物理定义

1. 逐时 2m 温度路径与峰值时间：检查日最高提取、午后回暖和峰值错位。
2. 短波辐射：明确累计量、累计起点与步长；不能把积累通量直接当瞬时通量。
3. 云量：总云量及可用层次，统一 fraction/percent 定义；无定义即缺失，不猜测。
4. 降水：累计重置、时段增量与成员发生比例分开；不能把概率与降水量当同一个变量。
5. 10m u/v 风：由分量推导风速/风向，保留海风或锋面转向时序；不能只用全天最大风速替代下午状态。

先从 active 全球集合产品实际存在且历史可回放的变量开始；不因字段缺失引入退役确定性或 republisher 产品冒充原生。区域产品仍遵循既有阶段边界。

## 进入实验前的硬检查

- 所有特征按当时可用 run 与目标日实际时区从逐时事实推导，禁止跨 run 或跨成员逐值拼接最好天气。
- 同一输入快照统一计算温度和物理特征，不把更晚物理 run 配给更早温度包。
- 允许显示缺失模式；不允许猜测 schema、单位、发布时间或隐式回填。
- 原生物理字段可用性先于模型拟合；至少满足现有历史训练/留出与 exact scope 激活合同，不能为凑样本降低门槛。
- 训练/选择/外层留出重建一次全链；本轮已用过的 09-12..09-19 只能作为开发/回归材料，不再冒充未见外层集。
- 有足够新的闭日历史后，再比较逐时物理条件候选与冻结现行 P0；云雨风联合模型必须同时改善或守住共同暖偏侧，不能只用共同冷偏侧通过。
