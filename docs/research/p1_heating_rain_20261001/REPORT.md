# 峰前加热窗降水：P0 / P1 能否接入（2026-10-01）

熊先生：「物理协变量：模型说的雨，站上到底下没下，目前是否可以进p0」「或p1」→「不要拉平均，不要拉峰后」→「做P1」。只读，生产未改。

## 1. 分格描述（build.py / an.py；08-15..09-22，P0 首决策 1,199 站日）
加热窗＝当地 09 时→实际最高温时刻；「模型说雨」＝Open-Meteo 历史短时效 09–15 时 ≥1 mm。
- 原始效应：加热窗下 ≥2 小时雨，最高温比同站 ±7 天干日低 2.0°C（中位），p25 低 3.3–4.0°C。
- 模型说雨且下 ≥2h：真值−P0 中位 +0.3（P0 已吃掉）。
- 模型说干却下 ≥2h（24 站日）：中位 −0.6，p10 −3.2，25% ≤−2°C（干日 5%）；P0 给真值桶 0.16、市场 0.156。发生在当天上午，P0（>36h）不可得。

## 2. P1 严格前推（build_dataset_p1.py / feat_p1.py / wf_p1.py；08-21..09-30，1,325 站日、5,340 决策点）

## 3. 为什么 P1 不要（diag_p1.py）
大样本里上午下 ≥2h 的 P1 并不比无雨日更偏：PIT 均值 0.45（无雨 0.46），PIT<0.1 为 7%（同 7%），真值−中心 p10/p50/p90 −1.1/−0.1/+0.7。§1 的「P1 冷尾太窄」来自 55 站日小样本，扩到 162 站日后消失。P1 本来就读实况温度轨迹与最后 6h / 6–10h 的降水，上午下雨造成的降温已经写在温度计上。雨日真值桶 <1% 的灾难 4.2%（干日 1.0%），但冷 6 / 暖 6、集中在 7 个站日，无方向可学。

## 结论
降水（加热窗实况）不进 P0（不可得）也不进 P1（预注册臂显著变差）。

## 4. 追加：METAR 滞后——「看不见的雨」（熊先生：「metar的更新时间太慢，是事后观测，而不是正在发生」）
latency_p1.py / latency_wf.py / latency_wf2.py。P1 已把最新报文的 `precipitation_present` 作协变量（metar_path_state、p1_observation_likelihood），问题是最新报有多旧。9–16 时 2,739 个 P1 决策点：最新可见报文龄中位 38 分钟、p90 68 分钟；到下一报中位 55 分钟。
- 神谕臂 B（决策时还看不到、下一报才出现的新雨，95 站日）：冷移 ΔLog −0.0005 [−0.0034,+0.0012]，加宽 −0.0003，均不显著——即便零延迟提前知道这场雨，上限也只有约 0.0005 nat/站日。
- 实时臂 A（最新报在下）、A'（在下且报龄 ≥30 分钟）、神谕 C（在下且下一报仍下）：全不过；神谕 D（下一报有雨）冷移显著变差。
- 诊断：「在下且持续」格 PIT<0.1 为 12%（基线 6%），P1 偏暖的冷尾集中在少数站日，冷移在其余站日付出更多。
结论：报文滞后不是瓶颈；更快的降水来源（ASOS 一分钟/MADIS 五分钟/雷达）在这一维度没有可收回的分数。

## 5. 追加：太阳辐射（熊先生：「太阳辐射呢」）
sun_feat.py / sun_diag.py / sun_wf.py。P0 已有辐射项（宪章 160/173/210/222：晴朗度 Kt 两侧 0.18/0.06；09-26 干净回放「整条辐射项对不平移分不开」）。站上不测辐射，P1 读 METAR 云量。本节问：模型预报的晴/阴（决策时刻可得的 Kt：forward 或 P0 回执版本）× 站上实际云量（09 时→决策时刻已见 METAR 平均云量；神谕＝决策后到 16 时），2,731 个 9–16 时 P1 决策点，Kt 三分位 0.50/0.63。
- 九格诊断：真值−P1 中心中位全在 −0.1～0.0，PIT 均值 0.43–0.50；「预报晴却阴」「预报阴却晴」都没有方向偏差，只是更难（p10/p90 略宽）。
- 前推（宪章 240）：实时两类意外按方向平移 ΔLog +0.0009 [+0.0002,+0.0015] 显著变差，加宽 +0.0009 显著变差；单看「预报阴却晴」也显著变差；神谕（午后真实云量）平移 −0.0004 [−0.0036,+0.0021]、加宽 −0.0009 [−0.0054,+0.0028] 不显著。
结论：辐射/云量意外不进 P1；连午后真实云量的神谕都分不出，接卫星辐照度也无可收回。P0 的辐射项维持现状。
