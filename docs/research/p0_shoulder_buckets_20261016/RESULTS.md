# P0 输给市场在哪个桶：肩部（2026-10-16，熊先生「我觉得不是中心的问题，现在是肩部桶的问题，继续打根因！」）

只读诊断，生产未改。样本同 `p0m_morning_side_20261016/joined.jsonl.gz`（10,597 行逐小时服务 P1 × 其 P0/P0-M × 当时盘口，48 站，09-01..10-06）。
脚本 shoulder.py、split_source.py、per_system.py。「肩部」= 众数 ±1 桶。

## 1. 熊先生的判断成立：上午众数多半是对的，输在肩部分配

上午（当地 07–13）P0 与市场**众数相同的行占 60%**，差一档 36%，差两档以上 4%。众数相同的行上 P0 照样每行输 0.157 nat。

众数相同、真值落在某个肩部的 1,125 行：真值落暖肩 51%。**谁判对了是哪一个肩**：

| | 07–09 时 | 09–11 时 | 11–13 时 | 07–13 时 |
|---|---|---|---|---|
| P0 | 0.678 | 0.649 | 0.631 | **0.651** |
| P0-M | 0.665 | 0.669 | 0.722 | 0.687 |
| P1 | 0.667 | 0.718 | **0.840** | 0.756 |
| 市场 | **0.771** | 0.782 | 0.836 | **0.801** |

（AUC：0.5 = 抛硬币，1 = 全对。）肩部分配 Brier：P0 0.235，市场 0.182；按 0.5 切判对：P0 58%，市场 73%。

- 当地 **7 点**（观测还很少）市场已经 0.77，P0/P1 0.67：市场用的是**开盘前就有、我们没有**的信息。
- 到 11–13 点 P1 靠观测追平市场（0.84 对 0.84）：观测能补，但补到中午才补上。

整体按桶位拆（上午，真值相对市场众数）：真值落在市场众数的行（53%）上 P0 给 0.38、市场 0.55，贡献差距 +0.22 nat 中的大头；
真值在肩部时两边给的概率相当（0.27 对 0.27、0.25 对 0.27）。也就是说：**P0 不知道「这次真值偏左肩还是右肩」，于是两肩各放一大块、众数放得少**；
市场知道偏哪边，就敢把质量收进众数和那一侧的肩。P0 对自身众数的平均校准是对的（±1 桶 0.22→0.22/0.24），缺的是**分辨力**，不是校准。

## 2. 信息不是在构造分布时被抹掉的

用 P0 的哪个量去判肩都一样：肩部比例 AUC 0.651、均值在众数桶内的位置 0.640、中位数位置 0.643（三者相关 0.89–0.91）；
前推 logistic 对数损失 0.665 / 0.667 / 0.664（抛硬币 0.693，市场 0.544）。**P0 自己就只有这么多肩部信息。**

| NOAA GEFS | 0.607 | 0.592 | 0.15 |

| ECCC GEM | 0.542 | 0.552 | 0.13 |

| 市场（同行） | 0.80 | | |

- 池比任何单家都好（0.65），合成本身没损失信息。
- **权重最高的 AIFS 对「偏哪个肩」零分辨力，IFS 也几乎为零。** 池权重（宪章 242 按站×模型）是按整条向量的 LogScore 拟的，
  ECMWF 靠把众数放对拿分，肩部判断不进权重。
- 六家中心离散度低的一半行 P0 0.696、高的一半 0.632（市场 0.819/0.788）：系统间打架会再磨平一点，但不是主因。

## 4. 根因（按层）

1. **P0 层·系统输入**：六家集合对众数桶内的半档位置几乎没有分辨力，ECMWF 两家为零；这不是合成或形状问题，是输入里没有。
2. **市场多出来的信息在开盘前**（7 点 0.77）：不是观测（我们的 P1 在 7 点也只有 0.67），是我们不采的东西——候选是更新更快的确定性/高分辨率区域模式（宪章 267 F 的六家原生确定性已经在采、只进 F 未进 P0）、或人对站点的局地经验。
3. **P1 的观测能补，但要到中午**；上午这段是 P0 肩部分辨力缺口直接暴露的窗口。

## 5. 下一步可测（需各自预登记，按站给结论）

- **F（宪章 267，挂牌前确定性六家中位＋站修正）对肩部的 AUC**：数据已在 `listing_forecast_f_v1.json` 逐站日落盘；若 F 在 7 点肩部 AUC 明显高于 P0，
  它就是缺的那块输入，接法是作 P0 的特征（宪章 201 形态：中心半档平移）——此前 201 是按整体 RMSE/LogScore 判的，没按肩部判过。
- **按肩部分辨力给系统加权**：ICON/GEFS 上调、ECMWF 下调，前推，看众数相同行的肩部 Brier 与整体 LogScore。

# 第二部分：从原始成员到服务 P0 逐步排查肩部信息（10-16，熊先生「从原始模型到校准后逐步排查，看哪一步把信息丢了」）

脚本 `pipeline_audit.py`、`split_sharpness.py`；读数 `readings_pipeline.json`、`readings_split_sharpness.json`。不涉及市场。

**方法**：3,578 个上午（当地 07–13）服务 P0，逐家取它当时入座那一轮的原始成员（`calibration_native_ensemble_historical_member_run`，
到货早于 P0 决策）与它用的系统证书，用生产自己的函数（`native_ensemble_p0._interval_probability` / `_calibrated_system_probability`）逐层重算。
**重算与 P0 存的各家向量逐位一致：15,646 个系统向量全部 TV ≤ 1e-6**——下面每一层就是生产实际走过的路径。

层：A 原始成员直接数桶 → B 加 0.5°C 核 → C 加证书偏差平移 → D 再加展宽系数与核规则 → E 再混气候（可靠度权重）→ 按 P0 自己的权重成池 → 池后各层（桥、辐射、宽度、尾混、压顶、下限）→ 服务 P0。
指标：真值落在众数 ±1 桶时，判对哪个肩（AUC）；肩部比例的自信度（logit 斜率 b：b=1 刚好，b>1 欠自信，b<1 过自信）。

## 1. 池子每一层（以该层自己的众数为准）

| 层 | 判哪个肩 AUC | 众数命中 | LogScore |
|---|---|---|---|
| A 原始成员数桶·成池 | 0.685 | 22.2% | 2.204 |
| B + 0.5°C 核 | 0.692 | 22.0% | 2.100 |
| **C + 偏差平移** | **0.756** | **42.5%** | 1.352 |
| D/E + 展宽与核规则（气候混合权重全部为 1，未起作用） | **0.766** | 42.9% | 1.375 |
| 服务 P0（池后各层） | 0.746 | **44.4%** | **1.322** |

**没有哪一步把肩部信息丢掉。** 偏差平移这一步把肩部 AUC 从 0.69 提到 0.76、众数命中从 22% 提到 43%；展宽再 +0.01；
池后各层 −0.02（n≈1,200，AUC 标准误约 0.014，在噪声内），同时把众数命中和 LogScore 再提了一点。

## 2. 每一家单独看（以服务 P0 的众数为准）

| 系统 | A 原始数桶 | B +核 | C +偏差 | D/E +展宽 | 证书偏差 / 展宽 |
|---|---|---|---|---|---|
| ICON EPS | 0.612 | 0.673 | 0.681 | **0.688** | +1.00°C / 1.45 |
| GEFS | 0.513 | 0.561 | 0.646 | 0.649 | +1.26°C / 2.00 |
| AIGEFS | 0.508 | 0.599 | 0.611 | 0.627 | +1.97°C / 1.18 |
| IFS ENS | **0.498** | 0.553 | 0.606 | 0.615 | +0.62°C / 1.76 |
| AIFS ENS | 0.544 | 0.570 | 0.549 | 0.575 | +1.58°C / 1.31 |
| GEM | 0.529 | 0.575 | 0.569 | 0.565 | +1.31°C / 1.62 |
| 六家加权池 | 0.584 | 0.596 | 0.730 | **0.734** | |

- 校准对每一家都是**加**肩部信息（IFS 原始 0.50 → 校准后 0.62；GEFS 0.51 → 0.65），没有一家在校准里变差（AIFS、GEM 平）。
- **原始成员本身的肩部信息很弱**：六家原始成员数桶 0.50–0.61，只有 ICON 明显高于抛硬币。

## 3. LogScore 校准没有忽视它：服务 P0 的肩部比例自信度基本正确

| | 肩部比例斜率 b [95%] |
|---|---|
| 单家（C/D 层） | **0.08–0.39**：每一家单独都**严重过自信**（肩部比例说得太绝对） |
| 原始成员池 B | 0.20 [0.11, 0.30]：同样过自信 |
| 校准后池 D/E | 1.31 [0.85, 2.00] |
| **服务 P0** | **1.18 [0.82, 1.68]**（含 1） |

按前推日对服务 P0 的肩部比例再做一次 logistic 重校准：对数损失 0.6151 → 0.6238，**更差**。
即：服务 P0 的肩部分配已经是这批输入下能做到的自信度，再「说狠一点」样本外变差。

## 4. 结论（更正第一部分的 0.65）

- 第一部分 P0 判肩 AUC 0.65 是**只取「市场也同众数」的行**算的，那是被市场挑过的难子集；不加这个条件，上午服务 P0 以自身众数判肩 **0.75**。
- **构造与校准这条链上没有丢肩部信息**：偏差平移是加信息最多的一步，展宽持平，气候混合未启用，池后各层在噪声内。
  LogScore 校准把肩部比例的自信度调到了正确的位置（斜率含 1，再校准变差）。
- **肩部分辨力的上限在原始成员**：单家原始成员几乎不知道「偏哪个肩」（0.50–0.61），而且单家说得非常绝对（斜率 0.1–0.4）；
  成池加校准把它们拼到 0.75，已经是这六家成员能给出的上限附近。
- 要再往上，只能是成员层面的新信息：哪一家的**原始**成员在哪些站/提前量上肩部最准，或成员日最高温的提取方式（6 小时采样漏峰，[[six-hourly-sampling-miss-not-recoverable-20261003]]）。
