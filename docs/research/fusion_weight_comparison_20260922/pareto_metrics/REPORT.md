# 三个冻结候选：概率质量与经济证据

熊先生，中心权重占 **25%、50%、75%** 的三个候选已固定；逐站日权重、来源文件及相同 515 条样本的 hash 写入 candidates.json。本轮没有重训、调比例或按结果删样本。current 为共同基线。

概率侧比较完成：25:75 的 Bucket Brier、LogScore 最好；75:25 仍保留上一轮的中心 RMSE 优势，三者继续作为候选。**实际可兑现 EV 与 Log-growth 尚无法识别，不能把概率评分的改善当成已经实现的收益。**

## 先明确 OOS 资格

沿用 33 个非 ASOS 站、2026-08-28 至 09-19、23 日、515 个站日。各历史预测拟合只用当时可知标签，但这批历史已经参与候选发现和选择。本轮标为 `retrospective_asof_comparison`，不是新的独立未见 OOS。新增评分不会恢复被用过的外层资格；三个候选已经冻结，下一独立历史外层必须排除参与设计的日期。

本轮概率仍是完整服务后处理前的线性池，不代表最终 P0/P0-M/P1 服务。TAF 可用性选样、美国 ASOS 标签缺口等前轮限制继续有效。

## Bucket Brier / LogScore

Bucket Brier 对每站日计算 Σ_b(p_b−1{y=b})²，再等权平均，越低越好；不是取最可能桶的二元评分，也不除以 2。LogScore=mean log(p_truth)，越高越好；它就是 NLL 的相反数，不是一份独立于上轮 NLL 的证据。全部零命中计数为 0，没有删零或添加 epsilon 美化结果。

| 候选（中心:分布） | Bucket Brier ↓ | 相对现行 | LogScore ↑ | NLL 相对现行 |
|---|---:|---:|---:|---:|
| current | 0.730368 | 基线 | −1.584997 | 基线 |
| **25:75** | **0.727989** | **−0.326%** | **−1.580667** | **−0.273%** |
| 50:50 | 0.728185 | −0.299% | −1.581672 | −0.210% |
| 75:25 | 0.728505 | −0.255% | −1.583013 | −0.125% |

连续三日块 bootstrap，25:75 的 Brier 差 95% 描述区间为 [−0.004475, −0.000260]，50:50 为 [−0.004459, +0.000022]，75:25 为 [−0.004353, +0.000648]。25:75 的本窗 Brier 证据较强，但这是短历史、多候选、已经查看过的探索分析，不作正式晋级检验。三候选 NLL 区间均跨零。

前半窗三个候选的 LogScore 都略差于 current，后半窗都改善；75:25 的前半窗 Brier 也略差。不能把全窗均值改善描述为每段历史或每站都更好。

## Reliability / Resolution

以每个桶是否命中作 one-vs-rest 事件，每站日先等权再均分桶。本样本全部是 11 桶，因此平均单桶 Brier = Bucket Brier / 11。下表 REL/RES 是**平均单桶**分解单位，不与总 Brier 混用。

分档预先固定为 [0,.01,.025,.05,.1,.2,.3,.4,.5,.6,.7,.8,.9,1]。REL 越低表示该分档下预测概率与经验频率更接近；RES 越高表示这些分档的经验频率更能区分事件发生。它们是有限样本、分档条件下的描述量。

| 候选 | Reliability ↓ | Resolution ↑ | ECE ↓ |
|---|---:|---:|---:|
| current | 0.00100103 | 0.01685557 | 0.021174 |
| 25:75 | 0.00084768 | 0.01689723 | 0.019644 |
| 50:50 | 0.00087078 | 0.01695271 | 0.019869 |
| 75:25 | 0.00087961 | 0.01698923 | 0.020350 |

主分档下，25:75 校准误差最小，75:25 分辨率最高。但改为事先固定的 20 档后，REL 以 75:25 最小，RES 反而以 25:75 最高。三个候选较 current 的改善方向仍一致，**候选之间的细排不稳定**；不能用这个排名证明某候选获得稳定的新信息。日期块区间也未排除 REL/RES 无差异。

正确分解保留分档误差项：

\[
BS_{\rm mean\ bucket}=REL-RES+UNC+\text{binning correction}.
\]

例如 current：0.06639706 = 0.00100103 − 0.01685557 + 0.08264463 − 0.00039303。省略最后一项会错误地声称分解精确重构原始 Brier。经验频率只作评估，未反灌任何候选预测。

## 经济层：已经核对到哪里

首先按原预测实际可用的准确时点检查 515 条：

| 状态 | 站日数 |
|---|---:|
| 之前有快照，但没有该时点有效的快照 | 498 |
| 无之前快照 | 4 |
| 快照表面有效，但逐桶 book 时钟晚于预测时点 | 10 |
| 通过准确时点初步盘口核验 | 3 |

这会排除正常“预测发布后等盘口”的操作。因此在计算任何经济收益前另行固定等待规则：保持预测和权重不变，最多等待 300 秒，不超过原预测有效期或本地事件日开始，取**第一份实际已到达且有效的完整官方快照**，不挑更好价格。

| 发布后首份可执行盘口口径 | 共同站日数 |
|---|---:|
| 找到首份完整盘口 | **152 / 515** |
| 窗口内找不到完整盘口 | 363 |
| 152 条中可绑定当时库存版本 | 151 |
| 可绑定当时订单状态版本 | 151 |
| 有当时新鲜的真实账户权益记录 | **42** |
| 有当时市场 registry 快照 | 28 |
| 盘口、库存、订单、权益、registry 均具备的交集 | **28** |
| 已检查的 quote / registry / shadow 回执中含明确费用字段的站日 | **0** |

费用检查包含 JSON 嵌套字段，并非只看快照顶层。这里只能说**当前取到的历史证据尚未绑定费用合同**，不能声称所有历史存储绝不存在费用证据，也不能把缺失费用默认成零。唯一一份对应时间窗口的 shadow receipt 不能补齐所有站日，更不是反事实真实成交。

本地 archive.db 也检查了：其 WS 表缺 settlement_timezone、quote_expires_at 和 quote_freshness_policy_sha256，不能猜值补成当前 canonical 合同。未使用后来价格、mid、最后成交价或今天账户余额补齐。

因此三个候选的正式经济比较目前都是：

| 候选 | 可兑现 EV | 实际 Log-growth |
|---|---|---|
| 25:75 | 未识别 | 未识别 |
| 50:50 | 未识别 | 未识别 |
| 75:25 | 未识别 | 未识别 |

这些不是零收益，也不是无交易。缺关键证据与策略决定不交易必须分开。152 条价格可用的子集也不能冒充完整 515 条或未见 OOS。

## 最终验收怎么做

详见 ECONOMIC_CONTRACT.md：

1. **同一最终服务概率链**：先复现原 P0/P0-M/P1 消费链，不能把线性池入口当作最终交易概率。
2. **同一执行政策和真实成本曲线**：按逐档 YES ask、费用、最小份额、盘口有效期与固定成交规则求动作。Maker 不能假定成交；Taker 也要保留 FOK/部分成交及拒单约束。
3. **分开预测 EV 与实现收益**：EV_model=Σp_bΠ_b；实际结算 PnL=Π_y。候选自己预测更高 EV，不能自证盈利更强。
4. **一条共享资本时间线**：并发站日共用资金、预留、持仓与结算释放。Log-growth 按经资金流校正的账户财富路径计算，不能把独立站日的 log-return 直接相加。
5. **经济共同子集与缺口透明**：四臂只在完全相同证据资格的站日上比较；报告覆盖率和选择偏差，缺证据不填 0。
