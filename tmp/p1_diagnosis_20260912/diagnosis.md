# P1 温度路径、METAR 与最高温预测诊断

熊先生，本轮结论是：**最先要修的是 P1 的状态更新契约。现有四层模型在训练时看完整当时路径，服务时却经常看最后一次新高的路径；同温、降温报文只给旧概率续期，重新定根又会把旧温度状态放到新时钟下。** 这足以同时造成中心判断滞后、下午不及时收敛、以及错误地维持升温概率。之后才是目标标签、观测时间尺度、剩余升温模型及采集链的优化。

本轮交付是代码审查、45 站实证核查和离线候选实验。生产代码、参数、服务与交易开关均未修改。没有恢复被裁决暂停的旧 trajectory soft LR。

## 已确认的根因

### 1. 预测刷新被“新高才触发”的逻辑截断

[`p1_compiler.py:875`](/Users/xiong/weather/bayes_basket_target/p1_compiler.py:875) 在加入当前路径后，对没有新高、也不是 ASOS 后 AWC 重新接管的报文直接 `continue`。所以降温、停升、降雨、风变即便已经到达，通常不能产生新的概率。

[`production_worker.py:13112`](/Users/xiong/weather/bayes_basket_target/production_worker.py:13112) 的无新高分支直接复制 predecessor 的概率与气象 lineage，只推进 decision/freshness。注释仍然建立在“hard-bound-only 模式下没有新高就没有概率变化”的前提上；今天服务的已是 v9 四层模型，这个前提失效。

675 个时点中有 284 份是 reaffirmation。新鲜度门槛通过，并不代表预测所用温度、云和风已经更新。

**优化：把“接收新证据并刷新 P1”与“允许触发交易”分开。** 每份通过现有仲裁和 QC 的新报文更新预测状态；时钟推进也应更新阶段概率。交易仍遵守熊先生现行“同温和旧温不交易”的规则，预测刷新本身不能产生订单意图。刷新落在现有概率物化路径，不新增驻留服务，也不把只读计算塞进 SSOT 写者槽。

### 2. 重新定根把不同时间的状态拼在了一起

[`p1_compiler.py:697`](/Users/xiong/weather/bayes_basket_target/p1_compiler.py:697) 将重放 decision 抬到较新的根/分支时间；[`p1_compiler.py:878`](/Users/xiong/weather/bayes_basket_target/p1_compiler.py:878) 仍只在新高处输出；[`p1_compiler.py:489`](/Users/xiong/weather/bayes_basket_target/p1_compiler.py:489) 用截至该新高的 `trajectory_prefix` 构造气象状态，却按较新的 decision 计算剩余小时和区域模型当前值。

结果不只是“旧报文”：还会计算出 `旧时刻实况 − 新时刻模型温度` 的 `regional_live_gap_c`，制造当天模型偏冷的假象。

实测：

| 指标 | 结果 |
|---|---:|
| 675 时点中四层分支被选中 | 550 |
| 四层时钟比其 closing 报文晚超过 2 小时 | 320/550 |
| 当地 16 时仍记录 drawdown=0 | 119/135 |
| 当地 16 时记录的 drawdown 与已收实况相差 >0.5°C | 52/135 |
| 当地 20 时上述不一致 | 116/135 |

具体例子：ZGSZ 09-11，当地 20 时取到的 P1 刚于 19:55 写入，仍使用 16:00 的 33°C 新高、drawdown=0、momentum=+1°C/h；19:00 的 31°C 报文已经收到，实际回落 2°C。该 P1 的区域模型 live gap 同时记为 +3.8°C。应先修时间对齐，不能把这个 +3.8°C 当作可靠的当天模型偏差。

**优化：先构造截至 decision 的完整可用观测前缀，再在最新根上只生成一次当前预测。** `running_high`、`latest_temperature`、`latest_physical_state` 分开保存；分别记录 valid/receipt/commit、物理状态年龄和模型 run。历史逐新高重放保留原时钟，仅用于审计，不能充当当前状态。

### 3. 高频与低频来源接缝被当成真实升温速度

[`metar_path_state.py:436`](/Users/xiong/weather/bayes_basket_target/metar_path_state.py:436) 的 momentum 是最后两个相邻有效时刻的温差除以时间差，未区分来源、量化精度和平均窗口。

KSFO 09-09 的路径中，MADIS 21:55 为 33°C，AWC 21:56 的 T 组为 33.9°C；相邻相除得到 **54°C/h**，这个数确实进入服务特征。675 个时点有 46 份存储的 `|momentum| > 10°C/h`。这不能证明真实空气以该速度升温，更可能同时含有时间尺度和量化接缝。

训练样本构建器却明确只读 AWC，排除这些 soft carrier。调用同一个特征函数，并不能消除输入采样体系不同带来的偏差。

**优化：** 同源窗口内估计稳健趋势；对不同观测平均窗口与精度建模，避免跨来源的 1 分钟差分。使用 15/30/60 分钟的时间窗口或状态空间温度/趋势估计，保留不规则时间间隔、缺测和来源质量；训练和服务走同一个 canonical prefix builder。对 ASOS 的密集序列按相关性处理，不能将每分钟读数都当独立证据重复相乘。窗口、噪声与权重由历史消融选，不直接拍定裁剪阈值。

### 4. “会再升温”标签与“会跨结算桶”不相同

[`build_metar_phase_hazard_samples.py:600`](/Users/xiong/weather/scripts/build_metar_phase_hazard_samples.py:600) 把 `truth_tmax − running_high` 四舍五入为整数 °C；[`fit_metar_phase_hazard_artifact.py:320`](/Users/xiong/weather/scripts/fit_metar_phase_hazard_artifact.py:320) 训练 `delta_c >= 1`。但 [`metar_four_layer.py:481`](/Users/xiong/weather/bayes_basket_target/metar_four_layer.py:481) 把这个率强制赋给“已报最高桶以上”的总概率。

逐条用样本对应根的真实桶区间复核 39,881 条训练样本：F 站 6,522 条中 **230 条（3.53%）标签不一致**；C 站也有 53 条，包含开口桶等边界情况。

真实反例：KATL 08-12，running high=33.0°C，truth=33.3°C。旧标签为“不再升”；真实 registry 中 90–91°F 桶上界为 33.05556°C，因此结果已跨到 92–93°F。

**优化：** phase 的标签直接定义为 `ordinal(bucket(truth)) > ordinal(bucket(running_high))`；continuation 则对真实桶上下界积分，不能把最近整数 °C 当成所有站通用的桶阶。长期可先建连续剩余增温分布，再按 registry 边界投影。C/F、舍入边界、负温及开口尾桶共用同一几何合同。

### 5. 支持集退化会让阶段模型“已选中但未生效”

四层 receipt 的 `applied=true` 表示链返回了分布，不等于每一层都应用。550 份中 phase 真正 `APPLIED` 为 518 份，另 32 份为 `SPLIT_DEGENERATE`。当上层把某一侧挤成零概率，phase 无法按目标重分配；随后末端 0.001 地板才将小概率补回来，已经错过 phase。

KSFO 上述例子中，phase 算出再涨率 76.65%，但状态为 `SPLIT_DEGENERATE`；最终已报最高桶为 99.80%。不把 phase 预测 76.65% 说成服务概率，也不把它当真实升温概率的可靠预测——它同时受 54°C/h 接缝特征污染。

**优化：** 硬事实排除与数值/模型零严格分开。在阶段分配之前保持可行桶的正支持，或直接用经校准的条件分布构造两侧质量；末端地板与归一化顺序须一致回放。验收要检查阶段目标质量是否真正到达 served P1，不只检查顶层 `applied`。

### 6. 历史评估存在被提前可用化的报文

[`build_metar_phase_hazard_samples.py:268`](/Users/xiong/weather/scripts/build_metar_phase_hazard_samples.py:268) 实际使用：

```python
max(valid_at, min(canonical_committed_at, valid_at + transmission_allowance))
```

当前 allowance 为 60 秒。几分钟或数小时后才到的报文，会在样本里被提前到 valid 后至多一分钟。这个上限原本处理报文名义时间略早/晚的容差，不能用来压缩真实接收延迟。训练表也不存完整 prefix receipt/revision lineage，无法据现有表单独重建真实可用性。

**优化：** 训练、回测使用真实 receipt/commit；历史回填没有真实 arrival 的样本只能作气候/物理拟合，不能冒充可交易时点 OOS。根、物理特征、区域 run、truth revision、参数 artifact 均需按每折真实可用时间冻结；训练与评估必须重放实际服务组合。现有 walk-forward 分数不能证明用户所感知的响应速度已经合格。

## 慢于市场：已证实哪些环节，尚不能声称什么

4,637 份无更正 AWC 报文的时间链：

| 时间差 | 中位数 | P90 |
|---|---:|---:|
| 报文 valid → 本机 first_seen | 263 秒 | 3,977 秒 |
| 本机 fetch_started → fetch_completed | 4.46 秒 | 25.58 秒 |
| first_seen → canonical commit | 0.165 秒 | 8.61 秒 |

`valid → first_seen` 包含观测窗口、站端发布、上游转发、轮询和本机补采，不是纯网络延迟，更不是相对市场领先/落后的分钟数。09-10 的 1,509 份中有 500 份超过 15 分钟；几次大批补到占据主要长尾。09-11 为 1,642 份，中位数 213 秒、P90 428 秒，比前两天稳定。

代码还对 AWC 请求固定等到每分钟 +30 秒；该路径的请求会在单分钟内复用缓存。官方文档说完整 METAR cache 每分钟更新，不能据此推定所有 API 与每站都在固定 :30 发布。

已有官方 CLOB WS 历史快照，抽查与固定取样时点相邻；但本轮没有把每次价格迁移与同一事件的发布、接收、P1 更新、决策精确配对，也没有验证全量盘口连续性。**不能据这些快照给出“市场领先 X 分钟”的结论。** 市场还可能提前反映外部预报和局地信息；价格不是气象真值。

优化顺序：先阻止已收到的信息被忽略；再为每个来源记录 `valid/published(确实有才填)/first_seen/commit/p1_created/decision_created`，从现有官方 WS 配对 `market_move_at`。按站点发布节律进行有界自适应拉取，保留现有 provider 配额、去重及复用；使慢源超时不拦住快源提交，恢复时按原始事件顺序补齐并明确当前状态。无数据、接口故障与天气没有变化必须分开。

## METAR 硬下界之外，应该怎样用

1. **测当前状态与模型创新量。** 比较同一有效时刻的实测温度与 NWP 曲线，估计当日温度偏差及持续性。风速、露点、云与雨已经在四层特征中，第一步是让它们及时刷新。观测舍入范围进入软观测似然；0.1°C 是报文分辨率，不是传感器准确度。
2. **判断升温阶段和剩余增温。** 输出“还会不会跨当前桶”“如果跨，会跨多远”“峰值时间分布”。区分升温、平台、降温后的再次升温，允许异常实况令不确定性暂时扩大。不能把熵强行按时钟单调压缩，也不能把日落当成永不再涨的硬证据。
3. **读天气转折，而非只读温度。** 风向/海风转换、云底和对流云、降水开始/结束与持续时长、露点变化、站点当地太阳高度，是后续有物理含义的候选特征。现有简单云量只取最高覆盖等级，风只用速度；高云 BKN 与低云遮蔽不等价。每项须做独立消融，不能重复添加已测无收益的加速度。
4. **正确处理 T 组、最高温组与时间窗口。** 当前代码已有 `Tsnnnsnnn` 解码，不能再把“未用 T 组”说成根因。可增加 6 小时最高温组 `1snTxTxTx` 和 24 小时组 `4...` 的回溯区间约束与漏峰核对；只有窗口、站点结算规则和来源权利精确对应时，才能影响正式结算事实。不能把跨日/本地标准时窗口最大值直接塞进当前民用日期的硬下界。
5. **理解频率不等于新信息。** NWS ASOS 用户指南描述了一分钟样本与滚动五分钟平均、小时 T 组及滑动极值。密集报文高度相关；其精度、平均时段和 QC 标志必须随数值进入状态。该指南为历史 ASOS 文档，具体传感器/产品当前语义仍需逐源核实，不能推广为所有国家的 METAR 规则。
6. **SPECI 的沉默不代表不会再热。** AWC 文档列出的触发重点是显著风变、能见度/云底变化及危险现象，普通升温本身不保证触发 SPECI。因此“没收到新 SPECI”不能当停升证据；只有确认采集连续后，旧实况加时间消耗才提供有限的阶段信息。
7. **更正、迟到与丢报都要有明确定义。** COR 使用被更正报文的原有效时刻，因此不能按 valid 排序后丢掉修订；依现行规则停牌/审核。软预测重建、truth 修订和恢复决定均留 lineage，不能通过更改 `first_seen` 伪造历史可用性。

## 建议落地顺序与验收

**第一优先：完整状态刷新。** 改 `p1_compiler` 的最终状态生成与 `production_worker` reaffirmation，让无新高也能刷新预测；交易触发资格独立保存，`reported_high_advanced=false` 的刷新不产生订单。显式分开 `probability_computed_at` 与 `evidence_valid_at`。同时修复 reaffirmation 用 observation ID 字典序 `max()` 选择“最新报文”的审计缺陷，改按真实时间与 canonical revision 定位。

**第二优先：训练/服务输入与目标统一。** 同源稳健动量、跨源测量模型、真实桶 crossing 标签、真实到达时间、完整退化原因；状态缺失的处理不再靠无痕 `None`。上方形状缺证据时显式用经过对应训练的缺源模型/收缩，而不是把填入池化均值误读成当天模型确认。本次 550 份四层分支中 298 份是区域特征 `POOLED_FALLBACK`，53 份缺根曲线 shape。

**第三优先：剩余温度路径。** 在已对齐的完整状态上，拟合“剩余最大增温”的零增温质量 + 正增温条件分布；用同刻 innovation 修正连续曲线及其不确定性，再按正式 registry 积分得到结算概率。新 reanchor 必须与当前完整 P0/P0-M 校准栈一起验证，不能直接重新开启旧平移层，也不能把跨日静态中心校准等同于当天偏差同化。区域模型只在现行来源与历史激活合同允许的角色内使用。

**第四优先：接收/发布延迟。** 与前述时序日志一起定位每站每源的 P50/P95/P99、晚到批次、丢报窗口；再做 provider 并发隔离及发布节律适配。本机计算性能优化须测 `commit→P1` 和实际排队，不再以解析速度替代端到端响应。

正式验收必须覆盖全部 45 站、C/F、南北半球、上午/峰前/峰后、雨后再升、海风突变、夜间暖平流、COR、迟到、缺源、重复报文、平温无新高、日界线、DST 以及端点/开口桶。按闭日滚动训练与整日留出，日期和站日分块，不能随机拆报文；同一前缀下比较现生产、状态刷新、标签修正、完整候选。主指标用 CRPS/NLL/Brier、落桶命中和中心偏差，另报 50/80/95% 覆盖与区间宽度、峰值时间误差、误杀未来突破概率及观测后更新时间。未来日只登记到达与接口观察，不计 OOS。

下一个主线任务：**落地 P1 完整状态刷新与时间一致性修复，并用同一服务函数完成 45 站闭日严格重放；以此为基础再重训 phase/remaining-warming。**
